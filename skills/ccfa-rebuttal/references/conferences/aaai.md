# AAAI — Rebuttal 规则卡

> 依据：AAAI-27 周期（2026-10 出分 / 2026-10-31 rebuttal 截止）作者群信息汇总 + 社区经验。
> **AAAI-28 的具体日期与字符上限一定会变**，请以当年 CFP 与作者邮件原文为准。
> 标记：✅ 官方可查 · 🟡 社区经验 · ❓ 逐年会变或未经核实，必须自己核对当年 CFP（Call for Papers，征稿启事）

## 一句话

纯文本、每条 review 单独回复、字符级硬上限、不能改论文、审稿人之间互相可见、没有 OpenReview 式讨论期。
**这是所有形态里预算最紧的一种，rebuttal 的成败几乎完全取决于「笔墨分配」。**

## 关键参数

| 项目 | 值 | 标记 |
| --- | --- | --- |
| 提交入口 | OpenReview，每条 review 下方 `Add Author Response` | ✅ |
| 回复粒度 | **每条 review 单独回复**，不是写一整份 | ✅ |
| 上限 | 每条 **1,500 字符** | 🟡（引邮件原文："one response to each review, with a limit of 1,500 characters per response"） |
| 「总共 2500 字符」 | **是往年规则，当年已无此限制** | 🟡 |
| 计数方式 | 按单个字母和符号计（`apple` = 5 字符），空格/换行/Markdown 符号同样计费 | ✅ |
| 换算 | 1500 字符 ≈ 200–250 个英文单词 | 🟡 |
| 超额行为 | **超出上限无法提交** | ✅ |
| 跨审稿人挪用 | **不允许**，各条独立计数 | ✅ |
| 富文本 | 只能填文本；**不能上传 PDF、不能放图片、不能放外链或匿名链接** | ✅ |
| Markdown | 支持表格，但**一张表就会吃掉大半字数** | ✅ |
| 修改论文 | rebuttal 阶段**不能修改论文** | ✅ |
| 补新实验 | ❓ **政策存在冲突，见下节** | ❓ |
| 讨论期 | 无 OpenReview 式多轮讨论（一次性窗口，约 4 天量级） | 🟡 |
| 审稿人可见性 | **审稿人之间可以互相看到彼此的意见和分数** | 🟡 |
| Confidential Comment | 可给 AC/SPC 写保密意见，仅他们可见 | ✅ |
| AI Review | 不打分，但下方有回复按钮 | ✅ |
| 负分阈值（供 `--threshold`） | **6**（5 分 = borderline reject 算负分；6 分算正分） | ✅ |

## ❓ 能不能补新实验（必须自己核对邮件原文）

群内说法直接冲突，这是 AAAI rebuttal 最大的不确定性：

- 往年规则明确写过：`Authors should not provide new results during the rebuttal`。
- 当年有群友称：邮件里只禁止了外链和文件，没说不能补实验；群里多数人打算补。
- 出分前流传的截图写着「不能提供新实验结果」；也有人说官方态度是「不应该做」而非「禁止」。

**处理原则**：

1. 打开当年作者邮件原文，搜 `new results` / `new experiment`，以那句话为准，不要以群消息为准。
2. 若政策是「不应该做」而非「禁止」：优先用**论文里已有的证据**回答；确有必要补时，只补**最小控制实验**，并明确写成「we ran a quick check」而非「we completed a full study」。
3. **血的教训**：有人在其他会议上承诺「camera-ready 再补」，结果审稿人从 WR 直接降到 SR。空承诺比不补更危险。

## AI Review 要不要回

❓ 说法不一：有人去年没回 AI review 被 SPC 点名指出；也有人说去年邮件写的是不需要回复。

**稳妥做法**：给 AI review 写一条**简短**回复（3–5 句，指向具体章节即可），把它当成一次低成本的「AC 可见的认真度」展示。别为它挤占正分审稿人的预算。

## 时间线（AAAI-27 实例，用于理解节奏，不是承诺）

| 节点 | 时间 | 备注 |
| --- | --- | --- |
| 出分 | 10/24 约 20:15 北京时间起，按论文编号滚动放出 | 之前 OpenReview 的 Author Task 里能看到审稿人数量，但看不到分数 |
| 紧急审稿截止 | 10/26 AoE（北京 10/27 20:00 / 洛杉矶 10/27 凌晨 5 点左右） | 3–4 条 review 的论文此前可能补审稿人 |
| Rebuttal 截止 | 10/31（周六）AoE（北京 11/1 20:00 / 洛杉矶 11/1 凌晨 4 点左右，美国夏令时结束） | 截止前可反复编辑 |
| 最终结果 | 群内猜测 11 月底，有人说 11/30；**去年是 11/11 左右**，无官方确认 | ❓ |

**补审稿人的三个事实**（会直接影响你的工作量）：

- 当晚从 4 个变 5 个、新增一条 4 分的情况真实发生过；也有人第二天早上才多出一个。
- 补审稿人**不一定发邮件通知**——建议直接刷新页面看。
- 不保证一定补满 5 个，去年有论文最终只有 4 个审稿人。

**分辨第一轮 / 第二轮（紧急）审稿人**：看 review 提交时间。第一轮大约在 8 月底到 9/1；10/19–10/22 提交的一般是紧急审稿。第一轮由 SPC 亲自下场做的紧急审稿，**有可能不计入页面显示的均分**。第二轮新增审稿人普遍比第一轮给分低（群内怀疑存在「报复性审稿」，❓ 未证实）。

## 分数怎么看（参考性一般，样本有偏）

- 满分 10 分。**5 分 = borderline reject，算负分；6 分算正分。**
- 多位群友认为：**负分的个数比均分更重要**。正分数量多于负分，才算进入「抽奖区」。
- 群内统计（127 篇，作者发在小红书，**存在幸存者偏差**——愿意填表的分数普遍偏高）：
  - 均分 5.5 以上：值得认真 re，录用希望大约 6–7 成
  - 均分 5.2 以上：大约 2–3 成
  - 低于 5.25：有人选择直接撤稿
- batch 之间差别很大，最终由 **AC 在自己 batch 内排序推荐**。有 SPC 称自己 batch 分数普遍偏低、CV 方向尤其 mean；也有做 CV 的人说过了 5.5 就算高分。
- 异常分数：8 分可能被 AC 当成普通正分看待（主要在评 oral 时有用）；**置信度只有 2 的 4 分，AC 可能不太重视；置信度 5 的 3 分要格外重视**。
- Rebuttal 后改分的情况不多：有人说只有约 7% 的论文会改分，还有约两成是降分（❓ 未经核实）。但也有人均分 re 完涨 1 分并被录用。
- 有人到处说「5.8 以下就撤稿」，群内普遍认为是在劝退竞争者——**不用理会**。

## AAAI 专属打法

1. **先算预算再动笔**：1500 字符 ÷ 平均词长 ≈ 200–250 词。4 条 review = 最多约 900 词的总盘子。
2. **编号化省字**：`W1`/`Q2` 对应问题，不复述原问题。
3. **实验压成一行**：`latency: 12ms vs 18ms (1x, same batch)`，别画表。
4. **先攻置信度高的负分审稿人**（他们最有杀伤力，且审稿人互相可见 → 说服他会带动其他人）。
5. **正分审稿人也要回**，但三句话封顶：致谢 + 答掉小问题 + 具体承诺。
6. **交叉引用必须写明是哪位审稿人的哪一条**，只写「见其他回复」会被降分。
7. 审稿意见写的根本不是这篇论文 / 明显事实性错误 / 审稿人自称不懂这个领域 → 用 **Confidential Comment** 告知 AC，必要时同时发邮件（群内提到 `workflowchairs@aaai.zendesk.com`，❓ 未经验证）。
8. 改进的是某个已有模型 → 去 OpenReview 找那篇原论文的 rebuttal，看他们怎么回答类似质疑。
