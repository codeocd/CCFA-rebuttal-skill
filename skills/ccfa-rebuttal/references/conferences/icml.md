# ICML — Rebuttal 规则卡

> 标记：✅ 官方可查 · 🟡 社区经验 · ❓ 每年会变，**必须核对当年 CFP**

## 一句话

近年走 OpenReview，形态介于 NeurIPS 与 ICLR 之间：**一次性 author response 为主 + 有限讨论**。
补实验被接受，但窗口通常比 ICLR 紧，所以**优先级排序比覆盖面更重要**。

## 关键参数

| 项目 | 值 | 标记 |
| --- | --- | --- |
| 平台 | OpenReview（部分年份/部分 track 用其他系统） | ❓ 核对当年 |
| 结构 | 每条 review 各一条回复 + 一条 global response | 🟡 |
| 长度 | 常有明确字符/词数上限或「限一次提交」的约束 | ❓ **必须核对** |
| 富文本 | Markdown 支持，表格可用 | 🟡 |
| 外链 | 允许但须匿名 | 🟡 |
| 补新实验 | 允许，审稿人普遍据此改分 | ✅ |
| 修改论文 | 一般不允许在 rebuttal 期重传 PDF | ❓ |
| 讨论期 | 有，但通常比 ICLR 短；审稿人是否必须回应，逐年不同 | ❓ |
| 审稿人可见性 | 互相可见 | ✅ |
| 打分 | 分数 + 置信度，刻度看当年 form | ❓ |
| 负分阈值（供 `--threshold`） | ❓ 刻度逐年变；1–10 刻度用 **6**，1–8 刻度用 borderline 分（常为 **4**）之下为负 | ❓ |

## 打法要点

1. **窗口短 → 先打「能翻盘的人」**：高置信度负分和 borderline 优先；三个低分里的最硬那条要给出**可一句话确认**的结论。
2. **实验只做「最小可说服集」**：一个参数敏感性、一个复杂度/延迟数字、一个对齐后的强基线。别开新战场。
3. **理论类质疑（ICML 高频）**：不要在 rebuttal 里推公式。用「假设在你的设定下为何成立」+「假设失效时实验表现如何」两句话处理。
4. **Global Response 里放 Summary of Changes**，即使讨论期很短，AC 也会读它。

## 常见坑

- 按 NeurIPS 的节奏规划讨论期，结果 ICML 窗口更短，追问发出去没人回。
- 把篇幅花在解释方法本身，而不是回应被点名的疑虑。
- 承诺补的实验没给时间点，被当成空承诺。
